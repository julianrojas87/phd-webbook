# 3. Cost-efficient publication of public transport data on the Web

*"Transportation is the center of the world! It is the glue of our daily lives. When it goes well, we don't see it. When it goes wrong, it negatively colors our day, makes us feel angry and impotent, curtails our possibilities"*
<div style="text-align: right">— Robin Chase, transportation entrepreneur, CEO of Zipcar</div>

APIs are recommended to (public) organisations by EU regulatory frameworks as the *way-to-go* strategy to enable interoperable data exchange. However the inherent costs associated with the development, deployment and maintenance of new APIs is often an obstacle. The Linked Data Fragments (LDF) conceptual framework encourages the study of alternative API designs that go beyond the traditional assumption of server-side systems having to carry the full load of resolving query requests. In this chapter, 2 thorough studies are presented about the associated computational costs and performance of an LDF-based API for publishing public transport timetables, particularly designed (but not limited) to enable the calculation of a fully client-side route planning algorithm.

The API in question is called a Linked Connections (LC) API. Linked Connections define a semantic data model and also a Linked Data publishing specification, that describes public transport schedules (of bus, train, tram, metro, etc) in term of Connections, where a Connection is an entity that describes the event of a vehicle departing at t<sub>0</sub> from a station S<sub>0</sub> and arriving on station S<sub>1</sub> at t<sub>1</sub>. According to the LC specification, a LC API will publish an ordered collection of data fragments (containing Connections) based on Connection's departure time. Fragments also include semantically described hypermedia links to the previous and next fragment (if any), which allows client applications to traverse and retrieve only those data fragments that are relevant for finding, for example, the fastest route between two given stations. The reference architectural design of a LC server is described, as well as mechanisms to efficiently publish live and historical data. Additionally an evaluation comparing traditional HTTP-based polling interfaces and publish/subscribe interfaces such as Server-Sent Events is done to assess the scalability and limitations of both approaches.

Unlike the other 2 chapters, the work presented in this chapter was not directly performed with the collaboration of real public transport operators, although multiple attempts were made with several Belgian operators. However, the studies were carried out entirely with real data from more than 20 real operators from around the world, thanks to the open data published by them on a regular basis.

This chapter is mainly focused on studying RQ2, to determine if alternative API design such as LDF-based APIs, can provide more cost-efficient solutions for publishing semantically interoperable data on the Web.
