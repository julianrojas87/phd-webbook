# 5.2 Review of RQ2 and H2

Despite counting with designs and implementations present in all the works presented in this PhD dissertation, LDF-based APIs were only thoroughly evaluated in [Chapter 3](ch_3_introduction.md) and partially in [Chapter 2](ch_2-introduction.md).

[Chapter 2](ch_2-introduction.md) presents an initial scalability evaluation of polling HTTP interfaces compared to push-based Websocket interfaces. The results showed a lower latency for Websocket interfaces but at the cost of higher CPU use. In [Chapter 3](ch_3_introduction.md) a similar evaluation was performed to compare polling-based interfaces (HTTP) against push-based (Server-Sent Events) for handling live public transport updates. This evaluation included a higher number of concurrent clients and confirmed that a polling strategy is more cost-efficient. [Chapter 3](ch_3_introduction.md) also presented a thorough evaluation of a Linked Connections (LC) API, which is in turn a time-fragmented LDF API designed for facilitating the execution of client side route planning algorithms such as the CSA (Connection Scan Algorithm). Results showed how the LC API is indeed less computationally costly and scales better than traditional APIs for public transport route planning, however the trade-off imposed by the LDF-based API design, tolls high on the query performance at client-side for larger transport networks, which nullifies the benefits of cost-efficiency on the server-side for practical scenarios that involve large datasets.

Based on this evidence I move onto rejecting H2. However, interesting results were obtained that showed that under certain conditions (e.g, for smaller transport networks), an LDF-based API could perform as good as and even outperform a traditional server-side route planning API when the number of concurrent clients grows. This represents a promising opportunity, given that such conditions can be pursued when dealing with larger datasets. For example, by further fragmenting the data in ways where the resulting subsets can be treated individually and simultaneously as smaller datasets, where we can reach the higher performance and cost-efficiency observed in this work.
